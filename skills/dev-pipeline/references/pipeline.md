# 七阶段详细 SOP

本文件是 `SKILL.md` 的展开版。按阶段读，不要一次全读。

## 阶段 0 · 接单与分级

1. 用一两句白话复述：「你要的是……，我理解对吗？」不要逐字重复需求。
2. 判断信息缺口。只有「用户才能决定」的事才问，例如：给谁用、数据重要不重要、要不要保留原数据、有没有指定位置。技术选择（语言/数据库/打包方式）一律不问。
3. 需求含糊时先给 3 个具体例子让用户挑（像点菜），再问一轮；每题 2–4 个选项，写「效果 + 代价」，标推荐项。
4. 最多一轮、一次问完。用户不答或说「你定」→ 按推荐做，并用一句白话说明你替他定了什么。
5. 判档位（L0/L1/L2），一句话告诉用户：「这件事不大，我走快线，大概十几分钟」。
6. 建 `todo_write`（阶段级）。L2 在计划确定后 `create_goal`。
7. 规模闸：登录/支付/服务器/多端同步这类超出本机单用户范围的需求，先给「最小可用一块（推荐）/换个更简单做法/确实要全量」三个选项，说明各自代价；不要闷头做半个系统。

## 阶段 1 · 勘查与选型

**先做，不要先写代码。**

```powershell
Get-Location
# 工作目录可写探测（写完立刻删）
Set-Content -Path ".dsh-write-probe" -Value "ok" -Encoding utf8
Remove-Item ".dsh-write-probe"
# 运行时与工具
$PSVersionTable.PSVersion
Get-Command python,py,node,dotnet,git -ErrorAction SilentlyContinue | Select-Object Name,Source
# 现有工程线索
Get-ChildItem -Force | Select-Object Mode,Name
```

- 本机没有 Python 时不要假设 Python 可用；没有 Node 同理。按 `references/archetypes.md` 的决策表选。
- 改用户已有程序：先看目录结构、入口、依赖、数据文件；先跑一次原有构建/测试作为基线；把原文件复制到 `.dsh-dev/backup-<时间戳>/`。
- 数据路径：默认 `%LOCALAPPDATA%\<ASCII 应用名>`；测试用 `APP_DATA_DIR` 指向临时目录。绝不把用户数据写进 Program Files 或工程目录里的临时位置。
- 工作目录不可写：用一句白话让用户换一个可写文件夹（或在 DSH 里切换工作目录）；不要默默写到别处。
- 选型结果写进 `plan.md` 的「技术方案」，包括：运行时、数据位置、打包方式、依赖、目录结构。

## 阶段 2 · 规格与计划

用 `templates/plan.md` 写 `.dsh-dev/plan.md`。硬要求：

- `## 用户原话` 逐字保留，不要改写。
- `## 验收标准` 每条必须能判定，并写「怎么验」；禁止「界面美观」「性能良好」。
- `## 这次不做` 明确非目标，防止范围蔓延。
- `## 运行与构建命令` 写确切命令；依赖由谁装、装到哪写清楚。
- `## 交付物清单` 写清成品、中文说明（必须含验收表/自检清单/已知限制）、验收记录、打包方式；这些也要有验收项，不能只写在「我的理解」里。
- `## 风险与回退` 至少写：本机缺运行时时怎么办、打包失败怎么办、改旧数据怎么回滚。
- `## 修订记录` 每次改计划都追加一行。

**L2 独立评审**：`subagent_fork` 开 `reviewer-1`，只读 `plan.md` 和用户原话，按 `templates/review.md` 写 `.dsh-dev/review-1.md`。有 `[必须改]` 就改计划；只有影响到用户可见范围/时间时才用 `ask_user_question` 问一次。没有 `[必须改]` 直接进阶段 3。

## 阶段 3 · 垂直切片

目标：**最小的端到端能跑**，不是「把所有功能写完」。

- 必须能看到：程序能启动（或命令能跑）+ 一个核心动作 + 数据能写入并能读回。
- 例：记账工具先做「记一笔 → 看总额 → 关掉重开数据还在」，先不做导出/图表/分类。
- L0 主会话直接做；L1/L2 用 `subagent` 派 `builder-1`。
- 任务单模板：

```
你是本轮执行器。工程目录：<绝对路径>。计划：<plan.md 绝对路径>。
本轮只做垂直切片：<能启动 + 一个核心动作 + 数据能存能读>。
允许修改：<路径>。不要修改：<路径>。
基线：先运行 <命令> 并记录结果。
所有命令必须非交互（不要运行等待键盘输入的命令；用 --yes 等参数）；无法非交互就报告 BLOCKED。
完成标准：<...>。
完成后写 <工程目录>/.dsh-dev/reports/build-1.md，并以 BUILD=... 等标记结尾。
```

- 主会话收到 `BUILD=OK` 后必须自己再跑一次启动/自测，不能只信执行器。
- 证据落 `.dsh-dev/qa/evidence/`；`status.md` 更新到阶段 4。

## 阶段 4 · 分批实现

- 一次只做一组相关功能（例如「分类 + 筛选」算一组）；做完就自测，再做下一组。
- 每轮给执行器一个自包含任务单；同一时间只让一个执行器写代码；一轮只派一个小目标，做完就报告，不顺手扩大范围。
- 任务单写明「所有命令必须非交互」；需要键盘确认的流程改成 `--yes`/参数，或留给界面。
- 主会话每轮独立做三件事：看 `git diff --stat` / 文件清单是否越界；跑构建；跑自测（至少核心路径）。
- 有 git 的项目：每轮绿灯后 `git add` + `git commit`（提交信息写清做了什么）；没有 git 就用 `.dsh-dev/backup-*` 和 `status.md` 记录。
- 发现范围变大：升 L2，补计划/评审/垂直切片，告诉用户一句。
- 更新 `status.md`：阶段、迭代、当前子代理、下一步、证据。

## 阶段 5 · 独立验收与修复

**测试员必须新开**（`tester-1`），用 `subagent` 执行器预设。提示词要点：

```
你是独立测试员，只读源码，可运行程序/测试，不得修改任何源码或数据文件。
工程目录：<绝对路径>。计划与验收标准：<plan.md 绝对路径>。
启动/自测命令：<...>。数据目录：<...>。
必须真跑：逐条验收标准给「方法 + 结果 + 证据」；GUI 无法自动操作的写 BLOCKED 并给人工步骤。
写 <工程目录>/.dsh-dev/qa/qa-<N>.md（按 templates/qa.md），结尾 QARESULT=PASS|FAIL|BLOCKED。
额外加一条来自用户原话的测试，并说明加了什么。
```

- 报告四块必须齐：新问题（严重/一般/建议 + 复现步骤 + 证据）、上轮回归、计划偏差、未覆盖/阻塞。
- 测试员不能改源码；主会话在它跑完后检查 `git status`/文件时间，确认没有越界修改。
- FAIL：把报告原路径 `send_message` 给同一个 builder，要求逐条修并重新自测；修完再新开 `tester-2` 复测，必须回归上一轮所有问题。
- 修复轮数：L1 ≤ 2 轮，L2 ≤ 3 轮。到上限还没全过：如实交付当前最好版本，两栏写「现在能用什么/哪里还不行」，给三条出路，并给最后一轮 QA 报告路径。

## 阶段 6 · 打包、交付与维护

1. 按 `references/archetypes.md` 生成最终产物（exe/one-folder/zip/html）。
2. 安装到最终位置（不是临时构建目录）；创建桌面快捷方式（放不了要说明原因）。
3. **干净启动测试**：从最终位置双击/启动，不依赖开发命令；关掉再打开，数据还在。
4. 主会话照 `README.md` 的用户步骤走一遍；走不通就改说明或改程序。
5. 写 `.dsh-dev/delivery.md`（用 `templates/delivery.md`）：这是什么、怎么打开、怎么用、数据位置/备份/恢复、自验清单、已知限制、卸载、以后怎么改、验收表。
6. 用 `present` 标出成品（exe/zip/说明书）。
7. 最终消息按七段：这是什么 → 怎么打开 → 怎么用 → 数据/备份 → 自验清单 → 已知限制 → 以后怎么改。
8. 维护：更新项目 `AGENTS.md`（技术栈/命令/数据/完成标准）；有版本号就递增；告诉用户以后想改直接说，改前先备份数据。

## 用户中途插话 / 叫停

- 用户追加要求：如果当前轮次快结束，记到 `status.md`，下一轮 `send_message` 带上；如果会改变方案，等本轮结束再调整，不要打断正在写文件的执行器。
- 用户说「算了别做了」：`interrupt_agent` 所有子代理；保存 `status.md`；用一句白话说明已保留什么、以后可以继续什么。不要用归档/删除来停止。
- 用户问进度：`list_agents` 看子代理状态 + `status.md`，用三句话回答；不要贴日志。

## 上下文压缩 / 重启

- `plan.md`、`status.md`、`qa/`、`reports/` 是唯一事实来源；压缩或新会话后先读它们再继续。
- 找不到状态文件：从工程目录的源码/构建产物和最近一次 QA 报告反推，并在 `status.md` 记下「重建状态」。
- 不要凭记忆说「已经测过」；以证据文件为准。

## 计划模式 / Goal

- 如果会话处于 plan mode：只做阶段 0–2 的只读工作，用 `exit_plan_mode` 提交计划；批准前不派执行器、不写文件。
- L2 在计划确定后 `create_goal`，交付完成 `complete`；用户叫停 `pause`。L0/L1 不用 goal，避免自动续跑。
