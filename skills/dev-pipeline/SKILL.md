# 开发者模式 · 七阶段流水线

本技能只做一件事：**把「用户的一句话」变成「真跑过、数据安全、能交付的程序」**。细节按需读 `references/`，不要一次全读。

## 0. 开工必做

1. 读工程目录里的 `.dsh-dev/plan.md` 和 `.dsh-dev/status.md`（有就接着做，没有就从阶段 0 开始）。
2. 判档位：L0 快修 / L1 标准 / L2 完整；用一句白话告诉用户走哪条线。
3. 建 `todo_write` 清单（阶段级）；L2 在计划确定后 `create_goal`。
4. 用户最多回答一轮问题；其余自己定，并用一句白话说明你替他定了什么。

## 1. 七阶段

| 阶段 | 做什么 | 产物 | 关卡 |
| --- | --- | --- | --- |
| 0 接单分级 | 复述需求；最多一轮提问；定 L0/L1/L2 | `status.md` | G0 需求可懂、档位合理 |
| 1 勘查选型 | 工作目录可写、OS、Python/Node/.NET、打包工具、git；读现有工程；改旧程序先备份；选技术栈 | plan 的「环境/选型」 | G1 环境可行、数据路径明确 |
| 2 规格计划 | MVP/非目标/验收标准/技术方案/文件清单/运行与打包命令/风险回退；L2 独立评审 | `plan.md`、`review-1.md` | G2 每条验收标准可判定 |
| 3 垂直切片 | 最小端到端：能启动 + 一个核心动作 + 数据能存能读 | `reports/build-1.md` | G3 切片真跑通 |
| 4 分批实现 | 按功能小步实现；每批自测；主会话独立跑构建/自测并核对 diff | `reports/build-N.md`、`status.md` | G4 功能齐全、构建通过 |
| 5 独立验收 | 新测试员只读、真跑、逐条给证据；失败回传同一执行器；回归上一轮 | `qa/qa-N.md`、`qa/evidence/` | G5 独立验收通过或如实 BLOCKED |
| 6 打包交付 | 最终产物、安装到最终位置、干净启动、快捷方式、中文说明、验收表、自检、维护说明 | `delivery.md`、成品 | G6 交付可用、可维护 |

**L0 快修**：单文件、无新依赖、不改数据结构、不打包，≤3 条验收标准。主会话直接改，跑冒烟检查，交付；不写完整计划、不派 QA。
**L1 标准（默认）**：新小型程序或中等改动。简版 `plan.md`；builder 实现；tester 独立验收；修复上限 2 轮。
**L2 完整**：多文件、有数据、要打包、改现有程序、接外部依赖。完整计划 + reviewer 评审 + 垂直切片 + 干净环境安装测试；修复上限 3 轮。

## 2. 子代理：怎么派、怎么等、怎么停

协调者通过 `subagent` 派执行器（默认预设已经是 `dev-worker`），通过 `subagent_fork` 派计划评审（仅 L2）。

**任务单必须自包含**（子代理看不到用户对话），至少给：工程目录绝对路径、`plan.md` 绝对路径、本轮只做什么、允许改哪些路径、基线命令、完成标准、报告路径。

```
subagent({
  name: "builder-1",
  description: "实现记账工具",
  cwd: "<工程目录绝对路径>",
  prompt: "你是本轮执行器。工程目录：<绝对路径>。计划：<plan.md 绝对路径>。
本轮只做：<任务>。允许修改：<路径>。不要修改：<路径>。
基线：先运行 <命令> 并记录结果。完成标准：<...>。
完成后写 <工程目录>/.dsh-dev/reports/build-1.md，并以 BUILD=... 等标记结尾。"
})
```

- 启动后本轮可以结束，等完成通知；**不要轮询、不要空转**。用户催问时才 `list_agents` 看状态。
- 任务单里写清：所有命令必须非交互（不要运行等待键盘输入的命令，用 `--yes` 等参数）；一轮只派一个小目标，做完就报告，不顺手扩大范围。
- 卡住：`send_message` 纠偏；仍无进展 `interrupt_agent`；拆小任务重试或自己接手。常见卡点是执行器跑了需要键盘输入的交互命令。
- 修复：把 QA 报告原路径 `send_message` 回同一个 builder，不要重新开执行器。
- 复测：新开 `tester-N`，保证独立性。
- 用户叫停：`interrupt_agent` 所有子代理，保存 `status.md`。
- 一个项目同一时间只让一个执行器写代码；测试员只读、可运行程序，不得改源码。

**测试员提示词要点**：只读源码、可运行程序/测试；逐条验收标准给「方法 + 结果 + 证据」；必须真跑；写 `.dsh-dev/qa/qa-N.md`，结尾 `QARESULT=PASS|FAIL|BLOCKED`。
**评审员提示词要点（L2）**：只读 `plan.md` 和用户原话；写 `.dsh-dev/review-1.md`，分 `[必须改]`、`[建议改]`、`[通过]`；逐句核对用户原话；没[必须改]就不要多问用户。

## 3. 工件契约（必须遵守）

生成工程目录：

```
<cwd>/程序/<名称>/
  ...源码、构建脚本、README.md、AGENTS.md、dist/...
  .dsh-dev/
    plan.md  status.md  review-1.md  delivery.md
    reports/build-1.md
    qa/qa-1.md  qa/evidence/
    backup-<时间戳>/
```

`plan.md` 必含：`## 用户原话`（逐字）、`## 我的理解`、`## 范围（MVP）`、`## 这次不做`、`## 验收标准`（每条写「怎么验」）、`## 技术方案`（含数据存哪、怎么打包）、`## 文件清单`、`## 运行与构建命令`、`## 风险与回退`、`## 修订记录`。
`status.md` 必含：阶段、档位、迭代、当前子代理、下一步、证据、更新时间。
`qa/qa-N.md` 必含：结论、测试环境、验收标准核对表、新发现问题（严重/一般/建议 + 复现步骤 + 证据）、上轮回归、计划偏差、未覆盖/阻塞、证据清单。
`delivery.md` 必含：这是什么、怎么打开、怎么用、数据位置/备份/恢复、已知限制、卸载、以后怎么改、验收表。

机器可判标记（写在报告末尾，主会话自己解析，不贴给用户）：

- 执行器：`BUILD=OK|FAIL|BLOCKED`、`CHANGED=`、`RUN=`、`SELFTEST=`、`EVIDENCE=`、`BLOCKERS=`、`REPORT=`。
- 测试员：`QARESULT=PASS|FAIL|BLOCKED`、`QA_REPORT=`。

## 4. 质量门

- **G0**：需求复述一致；最多一轮问题；档位有理由。
- **G1**：工作目录可写；选型在本机可运行/可打包；数据路径明确；改旧程序已备份。
- **G2**：每条验收标准有验证方式；非目标明确；打包目标明确；风险与回退有。
- **G3**：从工程目录启动成功；一个核心动作；数据存/读通过；证据落盘。
- **G4**：MVP 全部实现；构建/自测通过；diff 在范围内；无关键 TODO。
- **G5**：独立测试员真跑；PASS 有证据；上轮问题回归；无未解释 BLOCKED。
- **G6**：从最终位置启动；双击/快捷方式可用；主会话照手册走一遍；验收表完整；数据备份/恢复说明在。

没过门不许说「完成了」。到修复轮数上限还没全过，就如实交付当前最好版本，两栏写「现在能用什么 / 哪里还不行」，给三条出路（再修一轮、先这样用、换思路），并给最后一轮 QA 报告路径。

## 5. 失败出口

| 情况 | 处置 |
| --- | --- |
| 执行器预设不可用/启动失败 | 一句话说明；主会话按计划自己实现；不反复重试 |
| 权限/沙箱拦住 | 一句话说明；让用户切换权限或换可写工作目录；不自动提权、不同一权限反复试 |
| 构建/依赖失败 | 读日志；补环境或换无依赖方案；只装计划里列出的依赖 |
| 子代理卡住 | `list_agents` → `send_message` → `interrupt_agent` → 拆小/接手；不轮询 |
| QA 不通过 | 原报告发回同一执行器逐条修；回归上一轮；L1 最多 2 轮、L2 最多 3 轮 |
| 用户叫停 | `interrupt_agent` 所有子代理；保存 `status.md`；说明保留了什么、可继续什么 |
| 无可用运行时 | 给 2-3 个可行替代；不静默装系统软件 |
| 离线 | 选无外网依赖方案；说明哪些功能做不到 |
| 上下文压缩 | `plan.md`/`status.md` 是唯一事实来源；压缩后先读文件再继续 |
| 旧数据/迁移 | 先备份、副本测试、迁移成功再切；失败可回滚 |
| GUI 无法自动验证 | 标 BLOCKED；用截图/窗口存在性/手册人工步骤补证；不谎报 |
