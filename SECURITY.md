# Security Policy

## Supported versions

| Version | Supported | Notes |
| --- | --- | --- |
| **2.x** | ✅ | Current line — native-subagent presets, no local HTTP bridge |
| 1.x and earlier | ❌ | End of life; v2 removed the old `coder.mjs`/`lib.mjs` bridge and its local `/api` commands |

Security fixes ship in new releases on the current major line. There is no guaranteed backport policy for older versions.

## Reporting a vulnerability

**Do not open a public issue for an unpatched vulnerability.**

Report privately through GitHub Security Advisories:

👉 **https://github.com/lingyingaojue/dsh-dev-mode/security/advisories/new**

You can also open the repository's **Security** tab and choose **Report a vulnerability**. The report stays private between you and the maintainer until an advisory is published.

Please include, when possible:

- Affected version of the plugin (`package.json` version, or the version shown by the plugin manager).
- DSH version (`dsh --version`), operating system, and preset involved (`dev` or `dev-worker`).
- A minimal reproduction: what you ran, what you expected, and what happened.
- The security impact you believe is possible (for example, unintended file writes, data exposure, or command execution).
- Redacted logs or evidence paths. Never include live tokens, cookies, API keys, session URLs, or personal data.

## Scope

This policy covers the artifacts this repository ships:

- **Presets and runtime configuration** — `cordis.patch.yml` (personas, tool mounts, subagent wiring).
- **Pipeline skill and templates** — `skills/dev-pipeline/**`, including the starter templates under `templates/`.
- **Repository automation** — `scripts/ci-check.mjs` and `.github/workflows/ci.yml`.
- **Display resources and docs** — `locale/**`, `docs/**`, `assets/**`, and the READMEs, where a defect could cause users to run something unsafe or expose data.

Examples of in-scope issues:

- Instructions or presets that silently bypass DSH permission/sandbox rules or escalate privileges.
- Prompt-injection paths in skill instructions or templates that cause destructive commands, credential access, or data exfiltration.
- Templates or pipeline steps that overwrite or delete user data without a backup.
- CI or tooling that leaks secrets or executes untrusted code.
- A consistent unsafe default in how generated programs store data or secrets (not merely a bug in one generated app).

## Out of scope

- **Vulnerabilities in DeepSeek Harness itself.** Report those to the DSH project: https://github.com/deepseek-ai/deepseek-harness.
- **Security of programs generated by the mode.** Developer Mode writes and runs programs in your environment with the permissions of the session; it does not sandbox them. You are responsible for reviewing what a generated program does before running or distributing it, and for the security of your own machine, data, and accounts. (If the preset's instructions reliably produce unsafe behavior, that *is* in scope — report it under the point above.)
- Third-party dependencies, operating-system issues, or plugin-market packaging.
- Issues that require physical access to the machine, or already-public information.
- Social engineering and denial-of-service against GitHub.

## What to expect

This is a volunteer-maintained project, so response is **best effort** and no fixed service-level agreement is promised. In practice:

- We aim to acknowledge a private report within about 7 days.
- We will investigate, keep you informed of the decision, and coordinate a fix and disclosure date with you.
- Credit is given in the advisory unless you ask to stay anonymous.
- There is no bug bounty.

Please follow **coordinated disclosure**: give us a reasonable window to release a fix (typically 90 days, or earlier if a fix ships) before publishing details. Do not access other people's data, degrade the service, or run destructive tests while researching — test against your own profiles and workspaces only. Good-faith research conducted under this policy will not be pursued or reported as a violation.
